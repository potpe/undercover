# Tech stack

- `backend/`: FastAPI and SQLAlchemy Core. SQLite is the offline/test default; `DATABASE_URL` selects the Supabase session pooler. Both dialects share Core queries in Postgres schema `undercover`, with at most two pooled connections in the backend process to leave session-pooler headroom. APIs cover claims, document reads, deterministic payouts, dispatches, evaluations, usage/time ledgers, decisions, sign-off, payment and record-built summaries/scores. Every operation has an `operation_id`, a one-line docstring and no optional request inputs; required nullable fields remain explicit. The backend owns the $1,000 limit, payment guards, run state, handler answer keys and scoring. Identical decision/payment replays return the existing records.
- `agent/main.py`: the hand-written synchronous claim graph retains its API-only claim/document/payout tools, structured decision, `interrupt()` sign-off wait and graph-owned payment. Both model nodes record OpenRouter-reported token usage and `usage.cost`; structured output includes the raw reply so usage is retained. Each invocation records active work, excluding the interval spent waiting for a handler.
- `agent/dispatcher.py`: a model-free synchronous LangGraph graph with no checkpointer. A list node fans out with one `Send` per selected claim, an additive reducer collects results, and `max_concurrency=N` caps workers. `RetryPolicy` retries only `ModelRateLimitError` and `ModelTimeoutError`; exhausted transient work stays in progress, while ordinary errors retain one fresh retry and second-failure handoff. The worker reaches the claim graph through one harness function.
- `agent/checkpoints.py`: each claim keeps its own thread and saver. A process-wide synchronous psycopg `ConnectionPool` uses `min_size=0`, `max_size=4`, `autocommit=True`, `prepare_threshold=0`, `dict_row` and `search_path=undercover`; a separate `PostgresSaver` per claim avoids a shared saver lock. Claims wait for a connection. Tests use isolated synchronous SQLite savers.
- `agent/tracing.py`: Langfuse keeps a stable claim/thread session before and after pauses. Claim config metadata adds `langfuse_tags` with `dispatch-<run_id>` or `evaluation-<run_id>`, so a whole run can be found without merging claim traces.
- `agent/service.py`: a separate FastAPI service on port 8002 starts dispatches/evaluations, works named claims and resumes sign-offs. One non-blocking slot permits only one dispatch/evaluation. The service creates runs through the backend, executes in the background, and marks stale active runs stopped at startup without losing claim checkpoints. `backend/agent_service.py` is the backend's only agent HTTP boundary; the dashboard never calls the service directly.
- `backend/evaluations.py`: seeding stores held-out sources and both handler decision sets in separate backend-only tables. Evaluations create fresh claim ids in both the primary key and JSON record, and copies never enter queue/dispatch selection. Held evaluation approvals finish unpaid, cannot be signed off, and clear saved checkpoints. Backend scoring treats undecided copies as zero-payout referrals and computes decision accuracy, payout accuracy within $1, cost of mistakes, straight-through rate, model cost per claim, active time per claim and whole-run time from its own records.
- `dashboard/`: React, Vite and strict TypeScript. The queue starts N-way dispatches and shows claim progress, record-built summaries and cost/time. The Scoreboard starts whole/tiny evaluations, lists newest first and links handler/agent comparisons to copy pages. Copy pages have no run/sign-off controls. The instructions page shows only the claim agent.
- `e2e/`: Playwright with isolated SQLite business/checkpoint state and a JSON-capturing stand-in agent on port 8003. Automated tests never load `.env`, contact hosted services or call a model.
- `data/`: approved business seed data plus the evaluation sources/labels used only by backend seeding and scoring. The claim agent never reads files or receives handler answers.

Python 3.12 with uv, all in the root `pyproject.toml`. Node 26. `npm run dev` starts backend, agent and dashboard with `.env`; `npm run seed` intentionally resets the selected database, including runs, evaluations and checkpoints. `uv run -m agent CLM-1001` works one named claim with no run; bare CLI queue execution is removed.
