# Tech stack

- `backend/`: FastAPI and SQLAlchemy Core. SQLite is the offline/test default; `DATABASE_URL` selects the Supabase session pooler. Both dialects share Core queries, with product tables in Postgres schema `undercover` and at most four pooled connections per process. APIs cover claims, section-level document reads, deterministic payouts, capped runs, to-dos, recovery, decisions, sign-off and payment. Every operation has an `operation_id`, a one-line docstring and no optional request inputs. The backend owns the approval limit from `data/company.json` and all payment guards. Identical decision/payment replays return the existing claim; changed ones are refused.
- `agent/`: the claim agent is a hand-written synchronous LangGraph graph with typed state, model/tool nodes, structured decision, `interrupt()` sign-off wait and graph-owned payment. The queue agent remains LangChain `create_agent`. Claim work uses `durability="sync"` and `PostgresSaver` in the same Supabase schema, or SQLite checkpoints in isolated tests. The synchronous psycopg connection works with Windows' default event loop. Langfuse groups each claim/thread's traces into one session, including resume after a pause. The default model is `openai/gpt-6-luna` with low reasoning; `MODEL_NAME` overrides it.
- `agent/service.py`: a separate FastAPI service on port 8002 for claim work, queue runs and sign-off resume. The backend calls `UNDERCOVER_AGENT`, default `http://127.0.0.1:8002`, after runs and saved sign-offs. Sign-off never waits for payment and stands if the agent is unavailable. Service startup and each run recover saved work before new planning; `uv run -m agent` starts a run through the same entry point.
- `dashboard/`: React, Vite and TypeScript. The queue shows current-run to-dos and controls; claim pages show activity, sections read, decisions, signing handler/time and paid time. Sign-off resumes the agent rather than calling payment from the browser.
- `e2e/`: Playwright with isolated SQLite business/checkpoint state and a stand-in agent on port 8003. Automated tests never load `.env`, contact hosted services or call a model.
- `data/`: the approved business seed data. The agent never sees `data/evals/`, which holds the answer key.

Python 3.12 with uv, all in the root `pyproject.toml`. Node 26. `npm run dev` starts backend, agent and dashboard with `.env`; `npm run seed` intentionally resets the selected database, including old checkpoints, while normal startup preserves work.
